01 · Approach

From three channels
to one color image.

01

Basic alignment

The blue channel serves as the fixed reference, while the green and red channels are aligned to it separately. A default search radius of 15 pixels tests every horizontal and vertical displacement from -15 to 15. For each possible (x, y) displacement, np.roll shifts the moving channel before it is compared with the reference channel. The displacement with the best score is kept. This basic search is used for the smaller JPEG images.

02

Image pyramid

The larger TIFF images use a five-level image pyramid, with each level half the width and height of the previous one. Level 0 contains the original image. With five levels, the smallest image is approximately one-sixteenth of the original width and height.

Alignment begins at the smallest level, where a 15-pixel search covers a much larger area of the original image. After finding the first displacement, moving to the next larger level requires doubling the (x, y) values to account for the doubled image dimensions. This doubled displacement already gives a close estimate, so the next search only needs a two-pixel radius. The small radius corrects minor errors caused by resizing while keeping the search fast. The same process repeats until reaching the original resolution.

03

L2 and NCC

Two scoring methods, L2 and NCC, compare how well the shifted channels match. L2 calculates sum((image_1 - image_2)²) and selects the displacement with the smallest result. NCC first subtracts the average value from each image, then calculates sum(center_1 × center_2) / sqrt(sum(center_1²) × sum(center_2²)). A larger NCC value represents a better match, so its negative value is used because the alignment function is written to select the smallest score.

Part of each image border is ignored while calculating the score because the scan edges and the pixels wrapped around by np.roll do not represent the photographed scene. This keeps the comparison focused on the interior pixels and helps prevent incorrect results. The exact crop values were selected experimentally and are discussed below.

02 · Small images

Basic JPEG alignment

The JPEG images are 8-bit, so their pixel values are converted to the range from 0 to 1 by dividing by 255, or 28 - 1. Each vertically stacked image is then divided into its blue, green, and red channels. Since these images are small and their displacements are limited, the green and red channels are aligned directly with the basic search. The offsets for both L2 and NCC are listed below each result in (x, y) order. The dropdown can also display the original unaligned combination for comparison.

03 · Large images

Multiscale TIFF results

The TIFF images are 16-bit, so their pixel values are converted to the range from 0 to 1 by dividing by 65535, or 216 - 1. After separating the blue, green, and red channels, a five-level pyramid is built for each one. The green and red pyramids are aligned independently to the blue pyramid, starting from the smallest level and continuing toward the original resolution. At every larger level, the previous displacement is doubled and refined within a two-pixel radius. The offsets computed using both L2 and NCC are listed below each result in (x, y) order, and the dropdown includes the original unaligned image.

04 · Collection selections

Additional images

The additional results use three TIFF scans from the Prokudin-Gorskii collection at the Library of Congress: Hut, Orangerie, and Boy on Bridge. All three are processed with the same five-level pyramid and both scoring methods. The alignment works well on every image, while L2 and NCC produce offsets that differ by no more than one pixel.

05 · Analysis

Failure and observations

Several border crops were tested because the image edges and the pixels moved from one side to the other by np.roll can interfere with proper scoring. A 25% crop was the most reliable choice for L2 and for most of the images. Lowering the NCC crop to 10% included more of the image in the score and improved Emir. A 5% crop improved Emir slightly more, but it also left too much of the border in the comparison and made several other images worse. Therefore, 25% was kept for L2 and 10% for NCC. Keeping these different values also shows how the two methods perform with different border crops.

L2 and NCC found the same alignment, or differed by only one or two pixels, for nearly every image. This happens because most channels still show the same shapes and details even when their brightness is different, so both methods agree on where the images line up. Emir is the main exception. His blue clothing is very bright in the blue channel but much darker in the red channel, so the same area has very different pixel values. L2 compares these values directly and selects the wrong red displacement. NCC removes the average brightness and adjusts the channels to the same scale before comparing them, so the brightness change has less influence and the 10% crop produces a much better alignment.
